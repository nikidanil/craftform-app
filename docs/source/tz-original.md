## О проекте

Приложение, позволяющее создавать формы для проведения опросов, получения обратной связи, принятия заявок, регистраций на мероприятия и не только.

## Функциональные требования

- Пользователь должен иметь возможность зарегистрироваться в приложении и войти в него.

- Пользователь должен иметь возможность просматривать и редактировать информацию своего профиля.

- Пользователь должен иметь возможность создавать формы, добавлять и настраивать поля в форме (тип поля, обязательность заполнения, название поля и т. д.).

- Пользователь должен иметь возможность получить ссылку на опубликованную форму, чтобы можно было отправить ее другим людям.

- Пользователь должен иметь возможность просматривать ответы по своим созданным формам в личном кабинете.

- Пользователь должен иметь возможность редактировать и удалять свои формы.

## Нефункциональные требования

- Приложение должно иметь хорошую производительность и быстрый отклик.

- Приложение должно быть легко масштабируемым и поддерживаемым.

- Желательно, чтобы приложение было адаптивным и корректно отображалось на различных устройствах и экранах.

### Технические требования

- Код должен быть написан на TypeScript.

- Приложение должно быть реализовано с использованием React.

- В приложении должен использоваться менеджер состояния.

- Приложение должно быть по максимуму покрыто тестами с использованием Vitest, Testing Library. Рекомендуется вести разработку через тестирование.

### Пояснения

- Для сборки может использоваться любой из инструментов (например, Webpack или Vite).

- Для стилизации можно использовать подход: CSS Modules, библиотеки компонентов shadcn/ui (Tailwind внутри самих компонентов).

- Логика взаимодействия с сервером может быть замокана (например, [через Postman](https://learning.postman.com/docs/designing-and-developing-your-api/mocking-data/setting-up-mock/), программу-сервер или же через другой инструмент / сервис).

## Страницы

Содержание всех страниц, а также описание их поведения.

Описания доступов:

- **public** — страница доступна для всех пользователей, включая анонимных пользователей (тех, кто не вошел в систему).

- **protected** — доступ к странице предоставляется только авторизованным пользователям.

    Если пользователь открывает такую страницу с неактивной сессией, то его сразу перенаправляет на страницу входа. При открытии страницы входа таким образом на ней появляется сообщение: “Для просмотра информации о пользователе необходимо войти в систему”.

- **unauthorized only** — страница доступна только анонимным пользователям, которые еще не прошли процедуру входа в систему.

    Если пользователь открывает такую страницу с активной сессией, то его сразу перенаправляет на главную страницу. При открытии главной страницы таким образом на ней появляется сообщение: “Вы уже вошли в систему”.

Для сокращения описаний поведения фраза в содержании страницы: “ссылка на <название страницы>/<URL>” означает, что при нажатии на этот элемент происходит переход к странице с этим названием или URL. Например:

- Ссылка “Войти” — ссылка на /login

    _При нажатии на ссылку “Войти” будет осуществлен переход на страницу /login_

- Кнопка “Домой” — ссылка на главную страницу

    _При нажатии на кнопку “Домой” будет осуществлен переход на страницу /_

### 1. Вход

**Адрес:** /login

**Доступ:** unauthorized only

**Содержание:**

- Форма, содержащая следующие поля ввода:
    - Email

    - Пароль

- Кнопка “Войти”.

- Ссылка “Зарегистрироваться” — ссылка на страницу регистрации.

- Информация об ошибке (отображать в случае возникновения ошибки).

**Поведение:**

- Поля должны должны проходить заданную валидацию (определить самостоятельно).

- В случае ошибок валидации поле подсвечивается красным и появляется текст с указанием на ошибку.

- Если валидация не прошла или хоть одно поле не заполнено, то кнопка “Войти” должна быть неактивной.

- При нажатии на кнопку “Войти” форма отправляется и происходит процесс входа.

- После успешного входа пользователь перенаправляется на страницу всех своих созданных форм.

- Если вход не удался, то сообщить об ошибке (например, “Неверный Email или пароль”).

### 2. **Регистрация**

**Адрес:** /signup

**Доступ:** unauthorized only

**Содержание:**

- Форма, содержащая следующие поля ввода:
    - Имя

    - Фамилия

    - Email

    - Пароль

    - Повтор пароля

- Кнопка “Зарегистрироваться”.

- Ссылка “Войти” — ссылка на страницу входа.

- Информация об ошибке (отображать в случае возникновения ошибки).

**Поведение:**

- Поля должны должны проходить заданную валидацию (определить самостоятельно).

- В случае ошибок валидации поле подсвечивается красным и появляется текст с указанием на ошибку.

- При нажатии на кнопку “Зарегистрироваться” форма отправляется и создается новый пользователь в хранилище.

- После успешной регистрации сразу же авторизовать пользователя в приложении и перейти на страницу всех своих созданных форм.

- Если регистрация не удалась, то сообщить об ошибке (например, “Введенный Email уже занят”).

### 3. Профиль пользователя

**Адрес**: /me

**Доступ:** protected

**Содержание**:

- Шапка со ссылками:
    - “Главная” — ссылка на /

    - “Новая форма” — ссылка /forms/new

    - “Профиль” — ссылка на /me

    - “Выход” — выход из системы и переход на /login

- Карточка пользователя с его данными в полях ввода (изначально без возможности редактирования):
    - Имя

    - Фамилия

    - Email

- Кнопка “Редактировать”.

- Информация об ошибке (отображать в случае возникновения ошибки).

- Если валидация не прошла или хоть одно поле не заполнено, то кнопка “Сохранить” должна быть неактивной.

- При нажатии на кнопку “Отменить”, карточка с данными возвращается в начальное состояние.

- При нажатии на кнопку “Сохранить”, данные отправляются и сохраняются, форма становится недоступной для редактирования и появляется кнопка “Редактировать”.

### 4. Конструктор формы

**Адреса:**

- /forms/new — при переходе по адресу создается новый проект, после чего сразу идет перенаправление на адрес /sites/:formId (`formId` — ID новой формы)

- /forms/:formId/edit — основной адрес конструктора конкретной формы

**Доступ:** protected

**Содержание:**

- Шапка со ссылками:
    - “Главная” — ссылка на /

    - “Новая форма” — ссылка /forms/new

    - “Профиль” — ссылка на /me

    - “Выход” — выход из системы и переход на /login

- Боковое меню со списком возможных полей формы. Типы вопросов:
    - Поле ввода для короткого текста

    - Поле ввода для большого текста

    - Список выбора из флажков (checkbox) или переключателей (radio button)

- Рабочая область формы
    - Поле для ввода заголовка формы

    - Поле для ввода описания формы

    - Место для добавленных вопросов

- Вопрос (появляется при добавлении в рабочую область)
    - Поле ввода тела вопроса

    - Варианты ответа (если выбран тип “список выбора”)

    - Обязательность (да / нет)

    - Кнопка “Удалить”

    - 6 точек (2 в вдоль оси X и 3 вдоль оси Y) для перетягивания поля относительно других

- Кнопка “Сохранить”.

- Кнопка “Удалить форму”.

- Информация об ошибке (отображать в случае возникновения ошибки).

- Сообщение об успешном изменении формы (отображать в случае успешного обновления).

**Поведение:**

- Боковое меню:
    - При перетаскивании поля из бокового меню в рабочую область, элемент добавляется в форму и становится новым вопросом формы.

- Рабочая область:
    - При перетаскивании вопроса из рабочей области за ее пределы элемент пропадает из формы.

    - При перетаскивании вопроса (за 6 точек) между другими внутри рабочей области, он меняет свое расположение относительно других вопросов.

    - По умолчанию новый добавленный вопрос является не обязательным.

    - При нажатии на кнопку “Удалить” поле удаляется

- Страница:
    - Поле “название формы” должно быть обязательным для заполнения.

    - Форма должна содержать как минимум 1 вопрос.

    - Если валидация не прошла или хоть одно обязательное поле не заполнено, то кнопка “Сохранить” должна быть неактивной.

    - В случае ошибок валидации поле подсвечивается красным и появляется текст с указанием на ошибку.

    - При нажатии на кнопку “Сохранить”, форма создается / обновляется и затем показывается сообщение об успешном создании / обновлении формы.

    - При нажатии на кнопку “Удалить форму” форма удаляется и происходит перенаправление пользователя на главную страницу.

### 6. Страница просмотра всех откликов на форму

**Адрес:** /forms/:formId/responses

**Доступ:** protected

**Содержание:**

- Шапка со ссылками:
    - “Главная” — ссылка на /

    - “Новая форма” — ссылка /forms/new

    - “Профиль” — ссылка на /me

    - “Выход” — выход из системы и переход на /login

- Название формы к которой относятся отклики.

- Список откликов:
    - Номер отклика в качестве заголовка

    - Дата

    - Ссылка “Перейти к отклику” — ссылка на /forms/:formId/responses/:responseId

- Поле выбора с вариантами для сортировки.
    - Сортировка по дате (по убыванию и возрастанию)

    - Сортировка по времени (по убыванию и возрастанию)

- Фильтр с выбором диапазона дат.
    - Выбор даты “от” (день, месяц, год)

    - Выбор даты “до” (день, месяц, год)

- Сообщение (при отсутствии откликов)

**Поведение:**

- Отклики подгружаются при скролле (если их больше 30).

- После выбора даты “от” / “до” происходит подгрузка новых данных с выбранным диапазоном.

- При выборе варианта сортировки происходит сортировка списка откликов по выбранному значению.

- Параметры фильтрации и сортировки также должны добавляться в URL-параметры.

- При отсутствии откликов, показать сообщение: “Для данной формы нет откликов”.
