# Глоссарий FormCraft

Единый словарь терминов проекта. Цель — чтобы автор ТЗ, разработчик,
тестировщик и Claude в коде/обсуждениях называли одни и те же сущности
одинаково. Если в обсуждении возникает термин, которого здесь нет, —
сначала добавляем сюда, потом уже используем.

## Пользователи и роли

### Пользователь
Любой человек, взаимодействующий с приложением. Делится на две роли:
**автор формы** и **респондент**.

### Автор формы (создатель)
Зарегистрированный пользователь, который создаёт формы и владеет ими.
Видит свои формы в личном кабинете, читает отклики, редактирует
и удаляет формы. Все страницы автора — `protected` (см. ниже).
В ТЗ также встречается просто как «пользователь».

### Респондент
Анонимный посетитель, который проходит опубликованную форму по ссылке.
В системе нет учётной записи респондента — каждый его проход создаёт
новый **отклик**, не привязанный ни к какому аккаунту.

### Анонимный пользователь
Посетитель приложения без активной сессии. Может открывать только
`public` страницы и `unauthorized only` (вход, регистрация).

### Профиль
Карточка автора с его данными (имя, фамилия, email), доступная
по адресу `/me`. Автор может посмотреть и отредактировать профиль.

### Сессия
Состояние «пользователь вошёл в систему». Активная сессия открывает
доступ к `protected` страницам и закрывает `unauthorized only`. Выход
из системы (кнопка «Выход» в шапке) сессию завершает.

## Объекты предметной области

### Форма
Главная сущность приложения. Состоит из:
- названия (обязательно),
- описания (необязательно),
- упорядоченного списка **вопросов** (минимум один).

Форма всегда принадлежит одному автору. Сразу после сохранения
доступна по публичному адресу `/forms/:formId` — отдельной операции
«публикации» в этом ТЗ нет.

### Вопрос
Элемент формы. Имеет:
- тело (текст вопроса),
- тип (см. ниже),
- признак **обязательности** (по умолчанию — нет).

Внутри формы вопросы упорядочены; порядок задаёт автор перетаскиванием.

### Тип вопроса
Один из трёх вариантов:
- **Короткий текст** — однострочное поле ввода.
- **Длинный текст** — многострочное поле ввода.
- **Список выбора** — флажки (checkbox, несколько вариантов) или
  переключатели (radio button, один вариант). Для этого типа
  у вопроса появляется список **вариантов ответа**.

### Вариант ответа
Текстовая опция внутри вопроса с типом «список выбора». Респондент
выбирает один (radio) или несколько (checkbox) вариантов.

### Обязательность вопроса
Флаг «да/нет» на вопросе. Если стоит «да» — респондент не может
отправить форму, не ответив на этот вопрос. На странице прохождения
обязательные вопросы выделяются (например, красной звёздочкой).

### Отклик / submission
Единичное прохождение формы респондентом: ответы на все заполненные
вопросы плюс дата и время отправки. У отклика есть номер (порядковый
в рамках формы), используется как заголовок в списке. Отклики хранятся
вместе с формой и удаляются вместе с ней.

В тексте проекта используем русский «отклик» во внешних надписях
и в общении; «submission» — в коде/типах, если требуется отличить
от UI-ответа.

### Ответ
Заполнение конкретного вопроса в рамках одного отклика (значение
текстового поля или набор выбранных вариантов). Множество ответов
формирует отклик.

## Доступ к страницам

### public
Страница доступна всем, включая анонимных пользователей. Пример —
страница прохождения формы `/forms/:formId`.

### protected
Страница доступна только пользователю с активной сессией. Анонимного
посетителя приложение перенаправляет на `/login` с сообщением:
«Для просмотра информации о пользователе необходимо войти в систему».

### unauthorized only
Страница доступна только анонимному посетителю. Если открывает
авторизованный пользователь — он перенаправляется на главную (`/`)
с сообщением «Вы уже вошли в систему». Так помечены `/login`
и `/signup`.

### Опубликованная форма
В контексте FormCraft — любая сохранённая форма: после сохранения
её можно открыть по `/forms/:formId` без авторизации. Отдельного
состояния «черновик / опубликована» в ТЗ нет.

## Конвенции UI

### Шапка
Общая навигация на всех `protected` страницах. Состав ссылок
описан в [`features/app-shell.md`](./features/app-shell.md).

### «Ссылка на ⟨страница⟩»
В описаниях контента страниц встречается фраза «ссылка на ⟨название⟩
/ ⟨URL⟩». Это означает, что при клике происходит переход к указанной
странице. Например, «Кнопка „Домой“ — ссылка на главную страницу»
≡ при клике переходим на `/`.
